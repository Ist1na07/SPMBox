# 恢复与故障处理

## 恢复收藏夹

完全退出 osu! 和其他数据库工具，在 **收藏夹管理** 选择备份，点击“恢复此备份”。
恢复整个 `collection.db` 与配对的 `collection.db.spmbox.json`，会回退备份后的收藏夹更改；当前状态先另存一份备份。

程序无法启动时，打开 osu! 目录的 `.spmbox-backups/<时间_UUID>`：

- `collection.db` 是原数据库，关闭游戏后可复制回安装目录。
- `state.json` 的 `manifest` 非空时，把该对象单独保存为 `collection.db.spmbox.json`；为空时不要保留当前不匹配的管理记录。
- `existed:false` 表示当时没有数据库，备份目录中没有 `collection.db` 是正常状态。

先保留当前文件副本，再手动恢复。手动完成配对恢复且确认没有写入任务后，才移除 `collection.db.spmbox.pending.json` 中断记录。

## 恢复游戏星数／评级

完全退出 osu!，在 **游戏内难度重排 → 恢复游戏数据库** 选择备份。
恢复整个 `osu!.db`，包括星数、评级及当时的谱面索引；之后的数据库更改也会回退。恢复前再备份当前文件。
`scores.db` 与谱面正文不在修改范围。

程序不能启动时，从 `.spmbox-db-backups/<时间_UUID>/osu!.db` 取出所需备份。
保留当前 `osu!.db` 副本，关闭所有相关程序后，把备份复制回 osu! 目录。
`state.json` 标明来源目录与操作类型。确认完整恢复后，可移除 `osu!.db.spmbox.pending.json` 中断记录。

## 收藏夹受保护／名称冲突

新收藏夹的管理 UUID 在旁边的记录文件中，名字如 `!7K Density`，没有可复制的可见长标识。
只有管理记录、唯一名称与成员列表都匹配才可更新／删除。

- 改名或增删成员：保留你的手动更改，不再覆盖；可恢复修改前的配对备份来恢复自动管理。
- 记录文件丢失：原收藏夹不被认领，同名创建也停止，不覆盖用户内容。应找回原记录或配对备份。
- 旧版长名：确认更新时改为短名，UUID 转存至记录文件；不会靠名称前缀接管。
- 废弃分类：仅自动删除已验证、未改动且在当前模型／速率范围的 RC Wildcard、LN Wildcard、Break；手动改动的保留。
- 移动 osu! 目录后路径绑定失效：保留原记录和备份，不要修改绑定强行接管未经检查的数据。

## 更新与缓存

应用数据可在 **设置与关于 → 打开应用数据文件夹** 找到。
更换 portable 程序时，保留该目录中的 `analysis-cache.ndjson`、`library.json` 与设置。
界面、收藏夹列表和命名更新不会使算法结果失效。adapter 1–3 缓存会兼容迁移；旧标签可还原的字段直接补齐。
仅缺少整谱回退归属的旧无标签谱面需在分类扫描时定向补算，已有星数仍可用于游戏内重排。

文件改动或切换到尚未分析的模型／速率才计算相应结果；切回已有组合使用缓存。
真正更换算法时重新计算受影响的结果。旧版本已经删除的数据无法恢复。
只有处理缓存损坏时，才在关闭程序后移走缓存文件重建；先保留副本，不要把清缓存当更新步骤。

锁文件所属进程仍在运行时拒写；已退出进程的锁可自动回收。游戏运行时拒绝写入或恢复任何数据库。
