# 收藏夹恢复与故障处理

## 正常恢复

1. 完全退出 osu! 与其他会写入收藏夹的工具。
2. 打开 SPM Box → 收藏夹管理。
3. 选择备份时间，点击“恢复此备份”，检查提示后确认。

恢复对象为整个 `collection.db` 及其 `collection.db.spmbox.json` 配对记录。
当前状态会先保存为新的备份，因而可以撤销这次恢复。

## 程序无法启动或上次保存中断

备份不依赖 SPM Box 才能使用。打开 osu! 安装目录的 `.spmbox-backups`，选择所需时间的子目录：

- `collection.db`：保存前的原数据库；可在关闭 osu! 后手动复制回安装目录。
- `state.json`：配对标识记录及原文件是否存在。

先保留当前数据库及标识文件的副本，再恢复。`state.json` 的 `manifest` 非空时，将该对象单独保存为
`collection.db.spmbox.json`；为空时不应保留当前不匹配的标识文件。
如果 `existed:false`，当时还没有数据库，目录中没有 `collection.db` 是预期情况。

`collection.db.spmbox.pending.json` 记录一次未完成操作；正常的“恢复此备份”会清理它。
手工恢复完整配对文件后，确认没有工具在写入，才移除该中断记录。
锁文件中的进程仍存在时程序会拒绝写入；已退出进程的锁可由软件自动回收。

## 收藏夹被保护，无法更新

如果名称标识、记录或谱面列表有手动变化，SPM Box 会停止更新该收藏夹。不要把标识复制到别的收藏夹。

- 要保留手动更改：继续将它作为用户收藏夹使用；删除/改掉名称中的标识前，保留副本。
- 要恢复自动管理：恢复修改前的数据库与管理记录备份，再重新预览、更新。
- 标识文件丢失：原自动收藏夹不会被认领。新创建的分类使用新的 UUID，原收藏夹保持不动。
- 移动 osu! 目录：路径绑定失效时先保留旧记录与备份。不要修改绑定以强行接管未经检查的数据库。

## 缓存或扫描问题

应用数据目录可从“设置与关于”打开。关闭 SPM Box 后移走 `analysis-cache.ndjson` 和 `library.json`
可重建全部分析；先保留副本，之后重新选择目录、分析。缓存中没有收藏夹唯一管理凭证。

未支持的键数/模式会跳过；损坏文件和分类错误会列入分析报告。分类失败的谱面仍可查看成功的 rating，
但不会进入分类收藏夹。修改谱面、模型或速率后重新分析，再创建收藏夹。
